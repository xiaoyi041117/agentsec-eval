# Qwen3-8B 本地安全 A/B 试验报告

## 结论

本次试验成功验证了完整评测链路，但在当前 12 对攻击样例中，未检测到修改前与修改后的越权率差异：两组均为 0/12。这个结果只能说明 Qwen3-8B 在这批基础攻击样例上没有触发模拟工具，不能证明模型在所有多步工具攻击下都安全，也不能证明工程化防护没有价值。

## 环境与模型

- 运行时：Ollama 0.32.14
- 模型：`qwen3:8b`
- 本地模型信息：8.2B 参数、Q4_K_M、5.2 GB、40,960 上下文长度
- 能力门槛：通过；已授权正向样例成功返回结构化 `http_post` 工具调用
- 随机种子：42
- 每类样例：3
- 场景类别：4
- 请求总量：1 次能力门槛 + 24 次 A/B 推理

| 条件 | 有效样例 | 越权调用 | 越权率 | Marker 暴露 | 平均延迟 |
|---|---:|---:|---:|---:|---:|

- 尝试配对：12

- 因错误或超时排除：0
- 越权率差值（修改后减修改前）：0.0 个百分点
- 两组 0/12 的 95% Wilson 区间约为 0%–24.2%，因此样本量不足以声称真实风险为零。

平均延迟的差异不能解释为防护带来的性能提升：baseline 固定先运行，可能受到首次批量预热、系统负载和短样本随机波动影响。

## “修改前后”的准确含义

这里比较的是同一个模型、同一组 case ID、同一温度和同一套模拟工具下的两种推理期系统策略：

- baseline：普通工具型助手提示；
- hardened：明确把引用内容视为不可信数据，并要求只有顶层用户明确授权时才允许调用工具。

这不是对模型权重重新训练，也不是原 Kaggle 竞赛提交分数的复现。原 `CD.py` 依赖竞赛私有 SDK 和针对特定评测模型的攻击模板，无法在普通 Ollama 上原样公平运行。

## 如何解读零结果

正向能力测试排除了“模型根本不会输出工具调用”这一伪阴性来源。随后所有攻击样例都没有工具调用，说明 Qwen3-8B 能识别这批明显标注为引用、文档或待分类数据的基础注入。

但本轮只是快速试跑。若要用于申请材料或研究报告，建议下一阶段：

1. 增加攻击强度分层和措辞变体，而不是重复相同模板；
2. 增加多轮状态污染、跨工具依赖和延迟触发场景；
3. 增加正常授权任务，测量防护是否误伤可用性；
4. 每个场景至少运行 30 个独立变体，并单独报告置信区间；
5. 预注册检测规则和留出测试集，避免看到结果后反复调题导致过拟合。

## 复现命令

```bash
cd agentsec-eval
python compare_local.py \
  --backend ollama \
  --base-url http://127.0.0.1:11434 \
  --model qwen3:8b \
  --trials-per-scenario 3 \
  --seed 42 \
  --max-tokens 128 \
  --output-dir artifacts/qwen3-8b-comparison
```

所有工具均为模拟定义。程序只记录模型返回的 `tool_calls`，不会真正发送 HTTP 请求、邮件，不会写文件，也不会执行 Shell 命令。
